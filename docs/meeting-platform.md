# 会場別の例会マッチング運営

## ひるのめぐろでの運用

`/admin?tab=surveys` の「管理する会場」でひるのめぐろを選ぶ。既存イベント・回答・会員アカウントはそのまま。

1. 会場設定で公開ホームページ、とみざわの会場識別子、開始時刻を確認する。
2. 自動準備の設定で暗号化する簡単ログインURL、開始から締切までの分数、QR枚数を設定する。既存接続情報は継続利用する。
3. 開催2日前の01:00にイベントを用意する。名簿未作成なら準備待ちとなるため、とみざわ側で作成後に再実行する。名簿と事業概要・会社PRが正しいこと、QRから会社を選べることを配布前に確認する。
4. 11:15入場・11:30開始・15分後締切なら、11:45まで回答できる。イベントごとの「受付・締切」で調整できる。
5. 来場した回答者だけ出席確認する。締切後に分析を開始する。中断やAI障害があれば分析を再開する。
6. 全員分の分析後、候補と引用元を確認して公開する。確かな根拠がなければ候補なしとする。本人には会場内の候補、参加者の希望、TASUKI全会員からの候補と相談・投稿導線を示す。

## 会場を増やす

全体運営アカウントだけが「会場設定・担当者」から会場を作成し、担当者の認証済みメールアドレスにその会場の管理権限を付与する。担当者はGoogleまたはメール認証でログインし、`/admin` を開く。複数会場を担当するときは会場を切り替える。

会場担当者には、その会場のイベント一覧、名簿、回答、出席確認、紹介候補、QRを提供する。自動準備設定はひるのめぐろだけに表示する。会場作成・権限付与、TASUKI全体の会員・投稿・広告・バックアップにはアクセスできない。各APIとQRページでイベントの所属会場を確認し、URLやイベントIDの書換えで他会場へ入れない。

他会場は担当者によるアップロード運用に統一する。弊社から他会場のとみざわシステムにログイン・アクセスしない。担当者が例会を作成し、自会場のとみざわシステムから「まちださがみ式」の名簿TXTをダウンロードしてアップロードする。氏名・会社名・事業内容を固定の列から取り込み、人数と原文をプレビューで確認してから確定する。席は表示しない。形式が異なるファイルは受け付けず、列の手動変更も表示しない。

取り込み後にテーブル数を設定し、QRを印刷・配布する。以降の登録・回答・出席確認・集計・公開はひるのめぐろと同じ。アップロードされた事業内容だけを使い、他会場の会員詳細からPRを追加取得しない。

他会場には接続URLの入力・自動準備の画面を出さず、APIと内部処理でも自動接続を拒否する。過去の設定で自動作成が有効になっていてもスケジューラーは他会場を処理しない。ひるのめぐろの既存の自動準備は維持する。

## 人数とアカウント

名簿と回答は1例会300人まで。QRは60テーブルまで対応し、27番目以降はAA・ABと表示する。共有Wi-Fiで200人が回答・結果確認する利用を想定した読取・送信制限。AIは小さな候補群に分けて照合し、原文の根拠と独立審査を保つ。200人の名簿取込・回答・候補到達は隔離環境でテストするが、実AIでの所要時間と当日の通信環境は別途実測する。

TASUKIアカウントは全会場で共通。同じメールアドレスは既存アカウントを再利用する。イベントと会場の所属は表示名ではなく内部IDで固定し、例会名・会場の表示名を編集しても管理権限は変わらない。

削除は確認画面を挟む。イベントの名簿・回答・紹介結果・所属紐付けは消すが、会員アカウントと他イベントは残す。自動準備の削除済み記録を保持し、勝手に再作成しない。

## 実績を確認して営業する

イベントカードの「会社情報を登録済み」は当該イベントと紐付いたアカウント数で、既存アカウントを含む。「紹介候補あり」は候補がある出席者数、「希望を記入した出席者」はマッチング対象の母数。未分析と候補なしを混同しない。新規ユーザー獲得数や実際の商談成立数として代用しない。

ひるのめぐろで、登録・回答の所要時間、回答率、集計時間、紹介候補の妥当性、担当者の作業量、例会後の相談・投稿を確認する。その実測と画面を導入説明に使い、他会場への提供前に担当者で権限・QR・名簿・接続を確認する。

## 検証

- `npm run typecheck`
- `node tests/meeting-platform-runtime.mjs`（隔離D1・認証入口のテスト用差替え。実APIの権限判定・200人回答・データ分離・削除を検証）
- `node --experimental-strip-types --test tests/meeting-schedule.test.mjs`
- `node tests/cron-runtime.mjs`（とみざわはモック。実認証情報や実名簿を使わない）
- `node tests/meeting-accounts-runtime.mjs`
- `node tests/meeting-acquisition-runtime.mjs`
- `node tests/meeting-auth-integration.mjs`
- `npm run build`

本番はアプリと `tasuki-meeting-scheduler` の両方をデプロイする。暗号化キーの値は表示・変更しない。
