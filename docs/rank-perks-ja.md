# ランクと特典

更新日: 2026-08-31

**招待して参加した仲間の人数**でランクが上がり、できることが増える。
**仲間を連れてくる理由**をここで作っている。

掲示板は人が増えるほど値打ちが出る。いちばん報いたい行いは「人を連れてくること」なので、
ランクの物差しはオファーの件数ではなく招待の人数にしてある。

## ランク

| ランク | 必要な人数（招待して参加した仲間） |
|---|---|
| SILVER | 0（はじめから） |
| GOLD | 10 |
| PLATINUM | 30 |
| DIAMOND | 50 |

上のランクほど、**場そのものを大きくした人にしか届かない**ようにしてある。1人や2人で
最上位まで行けると、ランクが「早く始めた人の印」になって、あとから入った人の目標に
ならない。

### 何をもって「招待した」とするか

**その人専用の招待コード（＝招待リンク）から会員登録が行われた時点で1人。**

- 会員には1人1つ、専用の招待コードがある（`invite_code`。マイページ →「仲間を招待する」に出る）
- 渡し方は2つ。**リンク**（`/join/<コード>`）を送るか、**コードそのもの**を口頭・名刺で伝える。
  受け取った人はログイン画面の「招待コードをお持ちの方はこちら」から入力して同じページへ進む
- そのページからGoogleで登録すると、`invited_by` に招待した人が入る（`registerInvitedMember()`）
- ランクはこの `invited_by` の数で決まる

**すでに会員の人には後から紹介を付けない。** 既存会員の付け替えを防ぐため。

**いまの利用状態では絞らない。** あとで運営が誰かを止めたときに、招待した人のランクまで
下がってしまうため。ランクは下がらない決まりなので、数え方のほうを合わせてある。

**ランクは下がらない。** 累計で決まる。期限を切って落とす作りにはしない。
仲間を連れてくるという善意の行為を「維持しないと失う」にすると義務感が出て、場が痩せるため。

しきい値は `rankThresholds`（`app/rank-perks.ts`）1箇所にある。数え方は
`getMemberStats()` と `getMemberRank()`（`db/data.ts`）。招待の入口は
`app/join/[code]/page.tsx` と `app/InviteCodeEntry.tsx`。

## 特典

| 特典 | 解放 | 中身 |
|---|---|---|
| 募集の延長 | GOLD | 期限が来た探しごとを1件につき1回だけ2週間延ばせる |
| 掲載文章の上限なし | GOLD | 本文が600字の制限から外れる |
| おすすめ業種を10枠 | GOLD | ホームの「あなたにおすすめ」に出す業種が 6 → 10 個 |
| 写真の複数枚投稿 | PLATINUM | 探しごとの写真が 1 → 5 枚 |
| 動画を投稿できる | PLATINUM | 探しごとに短い動画を付けられる |
| 予算での絞り込み | PLATINUM | 掲示板を、その案件の予算で絞り込める |
| 広告が10%OFF | PLATINUM | 出稿料が1割引き（**Web専用**） |
| 広告が30%OFF | DIAMOND | 出稿料が3割引き。10%OFFとは重ねない（**Web専用**） |

正は `rankPerks`（`app/rank-perks.ts`）。アプリ側（`mobile/src/constants/rank-perks.ts`）は
`scripts/sync-mobile-perks.mjs` が書き出す生成物なので、直接編集しない。
金額に触れる特典は `webOnly` を立ててアプリから外す（App Store 3.1.1）。

「近日公開」は画面にもそう出している。できていないものを「使える」と見せないこと。

### 「掲載文章の上限なし」の実際

会員には「上限なし」と伝えているが、コードには**2万字の天井**を置いてある（`descriptionLimit()`）。壊れた入力や貼りつけ事故からDBと画面を守るためで、ふつうに書いてここに当たる人はいない。

### 動画をまだ作っていない理由

R2の無料枠は保存10GB。スマホの30秒の動画は1本30MB前後なので、**300本で10GBに届く**。写真（1件250KB前後）とは桁が違う。

入れるなら、長さと画質の上限（例：30秒・720p）を先に決めて、超えたぶんをどうするかまで決めてから。それまでは「近日公開」と正直に出しておく。

### 選び方

特典は**露出と信用**、それと**広告を有利に使えること**に寄せてある。値引きや無料月は招待特典（`docs/referral-program-ja.md`）とぶつかるので入れない。

会員検索とオファーの書き出しは**プラン**の機能（スタンダード）。ランクでも配ると二重になって説明できなくなるので、ランク側には置かない。

注目ピンと業種別プロモーションは、上位ランクが一覧を独占して掲示板が痩せるおそれがある。だからどちらも**ひと月に1件**に絞ってある。ここを緩めるときは、一覧の見え方を必ず確かめること。

## 置き場所

**定義は `app/rank-perks.ts` の1箇所だけ。** 増やすとき・入れ替えるときはここを直す。

```ts
levelFor(introCount)          // そのオファー数でのランク（1〜5）
descriptionLimit(level)       // 本文を何字まで書けるか
photoLimit(level)             // 写真を何枚つけられるか
notifyIndustryLimit(level)    // おすすめ業種をいくつ選べるか
canExtendRequest(level)       // 募集を延ばせるか
canPinRequest(level)          // 注目ピンを使えるか
canPromoteInIndustry(level)   // 業種別プロモーションを使えるか
adDaysAhead(level)            // 広告を何日先まで予約できるか
adMaxDays(level)              // 広告を1回で何日出せるか
```

止めている場所（サーバー側）:

| 特典 | どこで止めるか |
|---|---|
| 掲載文章の上限 | `createRequest()` が `descriptionLimit(level)` で切り詰める |
| 写真の枚数 | `createRequest()` が `photoLimit(level)` で切り詰める |
| 募集の延長 | `extendRequest()`（`db/data.ts`）。1件につき1回は `requests.extended_at` で見る |
| 注目ピン | `pinRequest()`。月1件は `requests.pinned_until` の年月で数える |
| 業種別プロモーション | `promoteRequest()`。付いている業種以外は選べない。月1件は `promo_until` で数える |
| おすすめ業種の枠 | `PATCH /api/profile` が `notifyIndustryCap()` で切り詰める |
| 広告の事前予約・期間 | `GET /api/ads` と `POST /api/ads/checkout` が `adDaysAhead()` / `adMaxDays()` で絞る |

**画面は隠すだけ。実際に止めるのは必ずAPI側。**

## アプリとの関係（ストア審査）

アプリにも特典の一覧を出す。ただし**金額に触れる3つ（トップバナーへの出稿・広告の事前予約・広告期間の延長）は出さない**。アプリ内に価格・割引・購入への誘導を置けないため（App Store 3.1.1）。

アプリ用の一覧は自動生成する。手で書き写さない。

```bash
npm run sync:perks    # app/rank-perks.ts → mobile/src/constants/rank-perks.ts
npm run check:perks   # ずれていたら失敗する（CI用）
```

`webOnly` を立てた特典は、この書き出しで自動的に除かれる。

## 決まっていないこと

- 動画の長さ・画質の上限と、保存量が増えたときの費用
- ランクを会場ごとの表彰と結びつけるか（オフラインの運用が増えるので保留）
