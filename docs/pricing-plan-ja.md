# 無料会員と有料会員の線引き

更新日: 2026-08-31

## 考え方

> **みんなの役に立つ行動は無料。自分の商売のために使い倒すところを有料。**

紹介掲示板は、投稿が多いほど・紹介する人が多いほど価値が上がる。だから「見る」と「人を紹介する（ギブ）」は必ず無料にする。ここを有料にするとサービスそのものが痩せる。

守成クラブは会員数に上限がある閉じた市場なので、入口を狭くすると人が溜まる前に止まる。ベースは無料で広く入れる。

**お金の入り口は2つだけにしてある。** 会費（スタンダード）と、トップバナーの出稿枠。プランを何段にも刻むより、この2本のほうが説明が短く、実装も薄い。

## プランと線引き

| | 無料 | スタンダード |
|---|---|---|
| **月額** | 0円 | **1,000円** |
| **年額（20%OFF）** | — | **9,600円**（月あたり800円） |
| 探しごとの投稿 | **月1件** | **何件でも** |
| 掲示板を見る | ○ | ○ |
| 会員を探す（業種・エリア・会場） | ○ | ○ ※未実装 |
| **知り合いを紹介する**オファーを送る | ○ 無制限 | ○ 無制限 |
| **自社で請け負う**オファーを送る | **×** | ○ 無制限 |
| 探しごとでやり取りする（コメント） | ○ 無制限 | ○ 無制限 |

### コメントの見え方

**最初のひとことだけ、会員みんなに見える。2通目からは投稿者とその人だけ。**

込み入った話や金額の話がそのまま公開の場に出てしまうのを避けたい。かといって全部を非公開にすると、掲示板が静まりかえって見え、書く気も起きない。だから入口のひとことは公開に残し、そこから先を1対1にした。

- 会員以外ではない人の目には触れない（そもそも会員制）
- 非公開のぶんは**サーバーが渡さない**（`getRequestComments()` で絞る）。画面で隠すだけだと、通信を覗けば読めてしまう
- 相手を指定して割り込めないよう、投稿者以外が書いたものは必ず本人自身のやり取りに入る
- 掲示板のカードに出る件数も**公開ぶんだけ**。非公開まで数えると、開いても出てこない数が札に出て、だれと話しているかの気配まで漏れる
| 届いたオファーの中身を読む・返事する | **×**（件数と日付だけ見える） | ○ |
| プロフィール・ランク・招待 | ○ | ○ |
| トップバナーへの出稿 | 上位ランクなら可（別料金） | 上位ランクなら可（別料金） |

「見る・ギブする・やり取りする」は全プランで無制限。ここを絞るとサービスそのものが痩せる。課金するのは「自分の商売のために使い倒す」ところ。

### オファーの線引き

オファーには2つある。**線はここで引く。**

- **知り合いを紹介する** … 場に人を差し出すギブ。**無料のまま**。ここを止めると掲示板に何も返ってこなくなる。
- **自社で請け負う** … 紹介ではなく**受注**。自分の商売そのものなので**スタンダードから**。
- **届いたオファーの中身を読む** … 受け取るのがサービスの値打ちの中心なので**スタンダードから**。無料の人には「何件、いつ、どちらの種類で届いたか」までを見せ、名前と理由は**サーバー側で空にして送る**（画面で隠すだけでは通信を覗けば読めてしまう）。

送った側は無料のままでも、**自分が出したオファーのやり取りはずっと読める**。出したものが読めなくなるのは筋が通らないため。

止めているのは `createIntroduction()` / `getReceivedIntroductions()` / `requireOfferChatAccess()`（すべて `db/data.ts`）。画面（`app/BoardClient.tsx`・`app/ReceivedIntroductions.tsx`）は案内を出すだけで、APIを直接叩かれても通らない。プランが足りないときのエラーには `PAYWALL` の印を付け、`app/paywall-response.ts` が `paywall: true` に変えて返す。画面はその印を見て案内を出すので、文言を直しても案内は消えない。

投稿を月1件だけ残すのが要。ゼロにすると掲示板が空になるが、1件試せると「紹介が本当に来る」体験ができ、2件目を出したくなる。**その2件目が1,000円**という設計。

年払いは1年ぶんを前払いしてもらうかわりに20%引く。割引率は `YEARLY_DISCOUNT`（`app/plan-catalog.ts`）1箇所にある。

金額と表示名は `app/plan-catalog.ts`（**Web専用**）にある。`app/entitlements.ts` には金額を置かない。アプリ内に価格を出せないため。支払い周期（`BillingCycle`）は金額ではないので `entitlements.ts` 側に置いてある。

## トップバナーの出稿枠

会費とは別のキャッシュポイント。**上位ランクの会員だけが買える特典**にしてある。

| 項目 | 値 | 置き場所 |
|---|---|---|
| 料金 | **1枠1ヶ月 10,000円**（税込・都度払い） | `AD_SLOT_YEN`（`app/plan-catalog.ts`） |
| 枠数 | **1ヶ月あたり10枠** | `AD_SLOTS_PER_MONTH`（`app/ad-options.ts`） |
| 買える人 | **会員なら誰でも**。ランクで変わるのは値段（割引）だけ | `canBuyAdSlot()`（`db/data.ts`） |
| 割引 | PLATINUM 10%OFF / DIAMOND 30%OFF（重ねない） | `adDiscountRate()`（`app/rank-perks.ts`） |
| 申込み | **早い者勝ち**。埋まったら翌月へ | `reserveAdSlot()`（`db/data.ts`） |
| 更新 | なし。掲載したい月ごとに申し込む | Stripeは `mode: 'payment'`（購読ではない） |

ランク条件を付けているのは、**仲間を連れてくるほど枠が近づく**ようにするため。会費だけだと「払えば誰でも目立てる」になり、紹介し合う場という前提が崩れる。ランクは招待して参加した仲間の人数で上がるので、広告枠が「人を連れてくる」動機として働く。詳しくは `docs/rank-perks-ja.md`。

掲載はカルーセルの**先頭**に置き、自動で送る。案内バナー3枚はそのうしろ。出稿者には**見た人・押された回数・反応率**を返し、終わった月のぶんも3ヶ月は見返せる。次も買うかどうかはこの数字で決まるため。

画像を持っていない人向けに、見出しと会社名から**端末の中でバナーを作る**道も用意している。買ったのに何も出ない枠を作らないため。

仕組みと運用は `docs/ad-slots-ja.md` が正。ランクごとの特典は `docs/rank-perks-ja.md` にまとめてある。

## 探しごとの写真

一覧の見分けがつくように、探しごとに写真を1枚だけ付けられる。**運用コストが増えない形に寄せてある。**

- **縮小は投稿する人の端末でやる**（`app/resize-image.ts`）。サーバーでは変換しない。Workersの計算時間は従量なので、ここで作業させない
- **一覧用と詳細用を別に持つ**。一覧は長辺480px（5〜40KB）、詳細は長辺1400px（150〜250KB）。掲示板は1画面に何件も並ぶので、一覧用を小さく保つのがいちばん効く
- **1件につき1枚だけ**。増やせる作りにしない。書き込み回数と保存量が読めなくなるため
- **URLに版番号が入る**ので、1年キャッシュ（`max-age=31536000, immutable`）にできる。同じ人が2回目に見るときR2を読まない
- 保存先は既存のR2バケット（`AVATARS`）。新しいバインディングも課金対象も増やさない

R2は保存10GB・書き込み月100万回・読み出し月1000万回まで無料で、**外部転送も無料**。無料会員が月1件なら、1,000人で月1,000件・約290MB。1年で3.5GB程度で無料枠に収まる。

顔写真とバナー画像の配信も同じ理由で1年キャッシュにしてある（URLに `?v=` が入る）。掲示板は1画面に何人ぶんも顔写真が並ぶので、ここの読み出し回数がいちばん伸びやすい。

## 有料が切れたとき、データは取り上げない

- 過去の投稿は残る。新規が月1件に戻るだけ
- 掲載が終わったバナーは表示から外れるだけで、入稿した内容は消さない

経営者向けのサービスで「払わなくなったら消えた」は致命的なので、この方針は変えないこと。

## 紹介（招待）との関係

`docs/referral-program-ja.md` の「紹介1人＝1ヶ月ぶんのクレジット」は、プランによって意味が変わる。**仕組みは1つのまま。**

| 紹介した人 | 受け取るもの | 実装 |
|---|---|---|
| 契約している人 | 次回の請求から1ヶ月ぶん引く | 確定と同時にStripeの顧客残高へ入れる。プランは変えない |
| 契約していない人 | **スタンダードが1ヶ月使える** | `bonus_plan = 'standard'`、`bonus_period_end` を1ヶ月延長 |

## プランは2本立てで持っている

| 列 | 意味 |
|---|---|
| `plan` / `plan_period_end` / `plan_source` | **契約している**プラン。Stripeの購読、または運営が入れたもの |
| `bonus_plan` / `bonus_period_end` | **招待特典**で一時的に開いているプラン |

実際に使えるのは**2つのうち上のほう**（`currentPlan()`）。別々に持っているのは、**契約すると特典が消える事故を防ぐため**。

- 無料の人が招待特典でスタンダード中に、自分でもスタンダードを契約 → 特典は残る
- 特典が切れたら → **契約しているプランに戻る**。契約がなければ無料に戻る
- 契約している人が紹介した場合は、特典ではなく**お金で返す**（プランが上下しないため）

画面では、契約しているプランに「契約中」、特典で開いているプランに「招待特典」と出し、いつまでで、そのあとどこへ戻るかを書いてある。

無料会員が仲間を1人連れてくると有料機能を試せる。試した人が課金する。招待が集客と有料転換の両方をやる。

上限は**1人あたり通算6ヶ月ぶん**。年ごとに戻る枠ではないので、使い切ったあとの紹介は無料月にならない。

## コードの構造

判定は **`app/entitlements.ts` の1箇所だけ**。画面のあちこちに `plan === 'standard'` を書かない。**画面は隠すだけ、実際に止めるのは必ずAPI側。**

```ts
// app/entitlements.ts
currentPlan(state)                            // 期限切れなら free に落とした、いまのプラン
can(state, 'member_search')                   // 機能ごとの可否
limits(state)                                 // いまのプランの上限
remainingRequests(state, usedThisMonth)       // 無料は月1件、スタンダードは無制限
```

上限は `planLimits` の1箇所にある。無制限は `UNLIMITED`（= -1）で表す。JSONに載せるので `Infinity` は使わない。

止めている場所（サーバー側）:

- `createRequest()` … 無料なら今月の投稿数を数えて拒否
- `canBuyAdSlot(level)` … ランクが足りなければ出稿の申込みを拒否

会員のデータ:

```sql
plan            TEXT  -- free | standard（旧 'pro' / 'premium' は standard として読む）
plan_period_end TEXT  -- YYYY-MM-DD。空なら期限なし（会場・法人契約）
plan_source     TEXT  -- direct | organization | referral
```

`membership_status`（守成クラブの会員かどうか）とは**別の軸**。会員でなければそもそも入れない、会員のうえで無料か有料か、という二段になっている。

## 有料にする・戻す

```bash
# スタンダード（1,000円）にする。期限なし
npx wrangler d1 execute <D1_DATABASE> --remote \
  --command "UPDATE members SET plan='standard', plan_period_end='', plan_source='direct' WHERE email='member@example.jp'"

# 期限つきで付ける
npx wrangler d1 execute <D1_DATABASE> --remote \
  --command "UPDATE members SET plan='standard', plan_period_end='2027-03-31', plan_source='direct' WHERE email='member@example.jp'"

# 無料に戻す
npx wrangler d1 execute <D1_DATABASE> --remote \
  --command "UPDATE members SET plan='free', plan_period_end='', plan_source='' WHERE email='member@example.jp'"
```

会場ぐるみの契約は、その会場の会員をまとめて `plan='standard'`、`plan_source='organization'` にする。

## アプリとWebの違い（ストア審査）

App Storeのガイドライン3.1.1により、**アプリ内に価格・割引・購入への誘導を置けない**。

**アプリには、その人がいま使える機能しか出さない。**

- 「アップグレード」ボタン、価格、Webへの誘導文は一切置かない
- **出稿枠の申込みはWebだけ**。アプリにはバナーの表示しか出さない
- 契約はWebだけ。アプリは状態を反映するだけ

取得口も分けてある。

| 経路 | 使う場所 | 返すもの |
|---|---|---|
| `GET /api/entitlements` | アプリ・Web | 使えるかどうかと件数だけ。**金額・割引は含めない** |
| `GET /api/referral` | Webのみ | 無料月の残高を含む |
| `POST /api/ads/checkout` | Webのみ | 出稿枠の決済 |

将来アプリの中で売るなら、そのときはアプリ内課金（手数料15〜30%）が要る。当面は外部契約のみ。
