# 無料会員と有料会員の線引き

更新日: 2026-08-29

## 考え方

> **みんなの役に立つ行動は無料。自分の商売のために使い倒すところを有料。**

紹介掲示板は、投稿が多いほど・紹介する人が多いほど価値が上がる。だから「見る」と「人を紹介する（ギブ）」は必ず無料にする。ここを有料にするとサービスそのものが痩せる。

守成クラブは会員数に上限がある閉じた市場なので、入口を狭くすると人が溜まる前に止まる。ベースは無料で広く入れる。

## プランと線引き

| | 無料 | スタンダード | プレミアム |
|---|---|---|---|
| **月額** | 0円 | **1,000円** | **5,000円** |
| **年額（20%OFF）** | — | **9,600円**（月あたり800円） | **48,000円**（月あたり4,000円） |
| 探しごとの投稿 | **月1件** | **月2件** | **何件でも** |
| 名刺帳に保存 | **50枚** | **300枚** | **無制限** |
| 名刺をカメラで一括読み取り | × | × | ○ |
| 会員を探す（業種・エリア・会場・年商） | × | × | ○ ※未実装 |
| 届いた紹介の書き出し | × | × | ○ ※未実装 |
| 掲示板を見る | ○ | ○ | ○ |
| 人を紹介する（ギブ） | ○ 無制限 | ○ | ○ |
| 探しごとでやり取りする（コメント） | ○ 無制限 | ○ | ○ |
| 届いた紹介を受け取る | ○ | ○ | ○ |
| プロフィール・ランク・招待 | ○ | ○ | ○ |

「見る・ギブする・やり取りする」は全プランで無制限。ここを絞るとサービスそのものが痩せる。課金するのは「自分の商売のために使い倒す」ところ。

投稿を月1件だけ残すのが要。ゼロにすると掲示板が空になるが、1件試せると「紹介が本当に来る」体験ができ、2件目を出したくなる。**その2件目が1,000円**という設計。

年払いは1年ぶんを前払いしてもらうかわりに20%引く。割引率は `YEARLY_DISCOUNT`（`app/plan-catalog.ts`）1箇所にある。

金額と表示名は `app/plan-catalog.ts`（**Web専用**）にある。`app/entitlements.ts` には金額を置かない。アプリ内に価格を出せないため。支払い周期（`BillingCycle`）は金額ではないので `entitlements.ts` 側に置いてある。

## 名刺画像の保存サイズ

名刺は無制限プランがあるので、画像の大きさが運用コストに直結する。

- **読み取りは端末側で高解像度（長辺2400px）のまま行う**。精度はここで決まる
- **保存する画像は長辺1400px・JPEG品質0.8に縮小してから送る**。1枚あたり数MB → 300KB前後
- 読み取りは保存前に終わっているので、縮小しても精度には影響しない

R2は保存10GB・書き込み月100万回・読み出し月1000万回まで無料で、**外部転送も無料**。300KB換算なら10GBで約35,000枚。超えたぶんは1GBあたり月$0.015なので、10万枚（約30GB）でも月$0.30程度。

## 探しごとの写真

一覧の見分けがつくように、探しごとに写真を1枚だけ付けられる。**運用コストが増えない形に寄せてある。**

- **縮小は投稿する人の端末でやる**（`app/resize-image.ts`）。サーバーでは変換しない。Workersの計算時間は従量なので、ここで作業させない
- **一覧用と詳細用を別に持つ**。一覧は長辺480px（5〜40KB）、詳細は長辺1400px（150〜250KB）。掲示板は1画面に何件も並ぶので、一覧用を小さく保つのがいちばん効く
- **1件につき1枚だけ**。増やせる作りにしない。書き込み回数と保存量が読めなくなるため
- **URLに版番号が入る**ので、1年キャッシュ（`max-age=31536000, immutable`）にできる。同じ人が2回目に見るときR2を読まない
- 保存先は既存のR2バケット（`AVATARS`）。新しいバインディングも課金対象も増やさない

投稿できる件数はプランで上限があるので、保存量も自然に頭打ちになる。無料会員が月1件なら、1,000人で月1,000件・約290MB。1年で3.5GB程度で、無料枠の10GBに収まる。

顔写真の配信も同じ理由で1年キャッシュにしてある（URLに `?v=` が入る）。掲示板は1画面に何人ぶんも顔写真が並ぶので、ここの読み出し回数がいちばん伸びやすい。

## 有料が切れたとき、データは取り上げない

- 登録済みの名刺は見られる。新規の一括読み取りだけ止まる
- 過去の投稿は残る。新規が月1件に戻るだけ

経営者向けのサービスで「払わなくなったら消えた」は致命的なので、この方針は変えないこと。

## 紹介（招待）との関係

`docs/referral-program-ja.md` の「紹介1人＝1ヶ月ぶんのクレジット」は、プランによって意味が変わる。**仕組みは1つのまま。**

| 紹介した人 | 受け取るもの | 実装 |
|---|---|---|
| 契約している人 | 次回の請求から1ヶ月ぶん引く | 確定と同時にStripeの顧客残高へ入れる。プランは変えない |
| 契約していない人 | **プレミアムが1ヶ月使える** | `bonus_plan = 'premium'`、`bonus_period_end` を1ヶ月延長 |

## プランは2本立てで持っている

| 列 | 意味 |
|---|---|
| `plan` / `plan_period_end` / `plan_source` | **契約している**プラン。Stripeの購読、または運営が入れたもの |
| `bonus_plan` / `bonus_period_end` | **招待特典**で一時的に開いているプラン |

実際に使えるのは**2つのうち上のほう**（`currentPlan()`）。別々に持っているのは、**契約すると特典が消える事故を防ぐため**。

- 無料の人が招待特典でプレミアム中にスタンダードを契約 → 特典は残り、プレミアムのまま使える
- 特典が切れたら → **契約しているプラン（スタンダード）に戻る**。契約がなければ無料に戻る
- 契約している人が紹介した場合は、特典ではなく**お金で返す**（プランが上下しないため）

画面では、契約しているプランに「契約中」、特典で開いているプランに「招待特典」と出し、いつまでで、そのあとどこへ戻るかを書いてある。

無料会員が仲間を1人連れてくると有料機能を試せる。試した人が課金する。招待が集客と有料転換の両方をやる。

上限は**1人あたり通算6ヶ月ぶん**。年ごとに戻る枠ではないので、使い切ったあとの紹介は無料月にならない。

## コードの構造

判定は **`app/entitlements.ts` の1箇所だけ**。画面のあちこちに `plan === 'pro'` を書かない。**画面は隠すだけ、実際に止めるのは必ずAPI側。**

```ts
// app/entitlements.ts
currentPlan(state)                            // 期限切れなら free に落とした、いまのプラン
can(state, 'scan_business_card')              // 機能ごとの可否
limits(state)                                 // いまのプランの上限
remainingRequests(state, usedThisMonth)       // 無料は月1件、スタンダードは月2件
remainingBusinessCards(state, stored)         // 無料は50枚、スタンダードは300枚
```

上限は `planLimits` の1箇所にある。無制限は `UNLIMITED`（= -1）で表す。JSONに載せるので `Infinity` は使わない。

止めている場所（サーバー側）:

- `createRequest()` … 無料なら今月の投稿数を数えて拒否
- `createBusinessCards()` … 無料なら保存枚数の上限で拒否

会員のデータ:

```sql
plan            TEXT  -- free | standard | premium（旧 'pro' は premium として読む）
plan_period_end TEXT  -- YYYY-MM-DD。空なら期限なし（会場・法人契約）
plan_source     TEXT  -- direct | organization | referral
```

`membership_status`（守成クラブの会員かどうか。運営が承認する）とは**別の軸**。会員でなければそもそも入れない、会員のうえで無料か有料か、という二段になっている。

## 有料にする・戻す

```bash
# スタンダード（1,000円）にする。期限なし
npx wrangler d1 execute <D1_DATABASE> --remote \
  --command "UPDATE members SET plan='standard', plan_period_end='', plan_source='direct' WHERE email='member@example.jp'"

# プレミアム（5,000円）を期限つきで付ける
npx wrangler d1 execute <D1_DATABASE> --remote \
  --command "UPDATE members SET plan='premium', plan_period_end='2027-03-31', plan_source='direct' WHERE email='member@example.jp'"

# 無料に戻す
npx wrangler d1 execute <D1_DATABASE> --remote \
  --command "UPDATE members SET plan='free', plan_period_end='', plan_source='' WHERE email='member@example.jp'"
```

会場ぐるみの契約は、その会場の会員をまとめて `plan='premium'`、`plan_source='organization'` にする。

## アプリとWebの違い（ストア審査）

App Storeのガイドライン3.1.1により、**アプリ内に価格・割引・購入への誘導を置けない**。無料＋有料になったことで、ここの危険度が上がっている。

**アプリには、その人がいま使える機能しか出さない。**

- 無料会員のアプリでは、名刺の一括読み取り画面を**表示しない**。グレーアウトや鍵アイコンも出さない（「どこで買うのか」と聞かれる）
- 「アップグレード」ボタン、価格、Webへの誘導文は一切置かない
- 契約はWebだけ。アプリは状態を反映するだけ

取得口も分けてある。

| 経路 | 使う場所 | 返すもの |
|---|---|---|
| `GET /api/entitlements` | アプリ・Web | 使えるかどうかと件数だけ。**金額・割引は含めない** |
| `GET /api/referral` | Webのみ | 無料月の残高を含む |

将来アプリの中で売るなら、そのときはアプリ内課金（手数料15〜30%）が要る。当面は外部契約のみ。

## 決まっていないこと

- **年額と会場単位のまとめ価格**。月額は上の表で決まっている
- 「会員を探す」と「紹介の書き出し」は未実装。`entitlements.ts` に枠だけ用意してある
