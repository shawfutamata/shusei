# 広告の無料ガチャ

更新日: 2026-09-03

## 何のためにやるか

**ねらいは売上ではなく、掲示板の上を埋めること。** 開いたばかりの掲示板は広告の枠が空いていて、空いた枠は売っても埋まらない。「誰も出していないところに最初に出す」のは、出す側にとって決心の要る話になる。配って埋めてしまえば、次に買う人は「こう出るのか」を見てから決められる。

もう1つは、広告を出したことが無い会員に一度出してもらうこと。出稿の手順を通ってもらえば、次からは自分で買える。

## 決まりごと

| | |
|---|---|
| 期間 | `app/gacha.ts` の `from`〜`until`（いまは 2026-12-20〜2027-01-07） |
| 回数 | **お一人さま1回**。`gacha_draws` の主キーで守る |
| 当たり | バナー30日（1）／14日（6）／7日（28）／はずれ（65）※かっこは重み |
| 配る上限 | 合計 **210日**。届いたら以降は全員はずれ |
| 券の期限 | 2027-03-31 |

当たる確率は重みの合計（100）に対する割合なので、そのまま「30日が1%、14日が6%、7日が28%、はずれ65%」になる。

**100人が引いた場合の目安**は、1×30 + 6×14 + 28×7 = 310日ぶん。上限210日で止まるので、実際に配るのは最大210日（バナー1日350円で換算して73,500円ぶん）。バナーは1日10枠あるので、210日は延べ21日分の全枠にあたる。

## 作りで守っていること

- **抽選はサーバーで引く**（`drawGacha`）。画面で引くと、当たるまで押し直せる
- 乱数は `crypto.getRandomValues`。`Math.random` は実装によって種を推測できる
- 書き込みは `INSERT OR IGNORE` で行い、**そのあと読み直した行を正とする**。連打や通信のやり直しで2回届いても、勝つのは先に入った1行だけ。「引いたか」を先に調べてから書くと、その隙間に2回目が入る
- 期間の判定は**日本時間**。UTCで比べると、日本の0時〜8時59分が前日扱いになる
- 券は `ad_gifts` に日数で持つ。使うのは**掲載日数を全部まかなえるときだけ**。足りないぶんを値引きにすると、支払いが途中で止まったときに券だけ消える
- 券だけで足りる申し込みは **Stripeを通さず、その場で掲載を始める**。券を減らすのは掲載を始めたあと（先に減らして失敗すると券だけ消える）
- 券で出した枠は売上**0円**として記録する。広告の売上に混ぜない
- お支払いの用意（Stripeの鍵）ができていなくても、**券だけで出せる申し込みは通す**。券は当たった時点で約束したもの

## 運営の見かた

管理画面のダッシュボードに「引いた人／配った枠／うち掲載に使われた枠」と、当たりごとの人数が出る。**引いた数より「何日配ったか」を見ること。** 配った日数のぶんだけ、売れる枠が減っている。

## 変えるとき

`app/gacha.ts` を書き替えて push すれば、そのまま効く。

- 期間を変える … `from` / `until`
- 当たりやすさを変える … `prizes` の `weight`
- 全員に当てる … `miss` の `weight` を 0 にする
- 配りすぎを止める … `capDays` を下げる（すでに配ったぶんは戻らない）
- **もう一度やる** … `key` を必ず新しい名前にする。同じままだと、前回引いた人が引けない

7日未満の券は作らないこと。広告は1回7日からしか申し込めないので（`AD_MIN_DAYS`）、使えないまま終わる。
