# 毎日ガチャ（広告の無料券）

更新日: 2026-09-03

## 何のためにやるか

ねらいは2つ。

1. **毎日ここを開く理由を作ること。** 掲示板は「見に来る習慣」がついて初めて回る。1日1回だけ引ける形にしてあるのはそのため。
2. **掲示板の上を埋めること。** 開いたばかりの掲示板は広告の枠が空いていて、空いた枠は売っても埋まらない。誰も出していないところに最初に出すのは決心が要る。配って埋めてしまえば、次に買う人は「こう出るのか」を見てから決められる。

売上を狙うものではない。**配った枠のぶんだけ、売れる枠は減っている。**

## 決まりごと

| | |
|---|---|
| いつ引けるか | **いつでも。終わりを決めていない催し。** 1人1日1回 |
| 回数の守り方 | `gacha_days` の主キー（member_id, day）。日付は日本時間 |
| 1人の上限 | **月7日分**。届いたあとも引けるが、券は増えない |
| 全体の上限 | **月100日分**。届いたら誰が引いても券は出ない |
| 上限が戻る日 | 毎月1日（日本時間） |
| 券の期限 | **当たった日から90日** |

### 見た目は季節で変わる

**中身（確率と日数）は同じで、包み紙だけ変える。**

| 期間 | 回 | 見た目 |
|---|---|---|
| ふだん | 毎日ガチャ | 四つ葉・アプリの青 |
| 12/20〜12/25 | クリスマスガチャ | プレゼント箱・赤と緑 |
| 12/26〜1/7 | お正月おみくじ | 門松・紅白と金（大吉〜末吉） |

`gachaSeason()` は **上から順に見て最初に当てはまった回**を返す。日付を入れていない「ふだんの回」は必ずいちばん下に置くこと。次の季節の回は「12月20日から クリスマスガチャ が始まります」と先に知らせている。

### ホームでの出しかた

- **入口は「ジャンル別の案件検索」の下**。横長のバナー1枚ぶんの枠になっている
- **その日はじめてホームを開いたとき、モーダルが自動で開く。** 引いたら開かない。引かずに閉じた人にも、同じ日には二度とかぶせない（端末に日付を覚えさせる）
- 「今日」はサーバーが返した**日本時間の日付**を使う。端末の時計や時間帯がずれていても、1日に何度も開いたりしない
- 使い方の案内（チュートリアル）が出ているあいだは開かない

#### バナー画像

`app/gacha.ts` の各回の `image` にパスを書く。置き場所は `public/gacha/`。

| 回 | パス |
|---|---|
| ふだん | `public/gacha/daily.webp` |
| クリスマス | `public/gacha/xmas.webp` |
| お正月 | `public/gacha/newyear.webp` |

- **大きさは 1200×400（3:1）の横長。** WebP推奨
- **画像を置かなくても成り立つ。** 無い・読めないときは、色と文字だけの帯になる（差し替えで画面が壊れない）
- **画像があるときは、こちらの見出しを重ねない。** 用意された絵の上に同じことを書くと、絵の文字とぶつかって両方読めなくなる。日ごとに変わるひとこと（「今日のぶんがまだです」「3日つづけて」）だけ、左下に小さな札で出す

#### 運営のアカウント

`ADMIN_EMAILS` のアカウントだけ、**今日ぶんを引いたあとも何度でも回せる**。見た目や当たりの出かたを確かめるためのもので、**2回目以降は「お試し」**。記録（`gacha_days`）も券（`ad_gifts`）も増えない。増やすと、運営が回した数だけ配った枠の数字が膨らんで、実際に何日配ったのか分からなくなる。

画面には「もう一度回す」が出て、そのすぐ下に「記録も券も増えていません」と書いてある。

#### 引くところの見た目

**モーダルの端まで色を伸ばした「舞台」**にガチャ本体を置いてある。白い紙の上に絵を置いただけだと、催しをやっている感じが出ないため。舞台の色は回ごとに変わる（ふだんは青、クリスマスは赤と緑、お正月は紅白と金）。

- 後光は舞台の背景（`.gacha-rays`）。**絵そのものにも光が入っているので薄くしてある**。強くすると二重になって、絵より飾りが目立つ
- 紙吹雪は**当たったときだけ降る**（`.gacha-stage.is-win`）。ふだんから動いていると、当たった手ごたえが出ない。位置と色は決め打ち（毎回変えると、開き直すたびに別の絵になり、サーバーが作ったHTMLとも食い違う）
- 揺れも紙吹雪も、動きを止める設定の端末では止まる（`prefers-reduced-motion`）
- いちばん上の賞（A賞）だけ金色にしてある。どれが目玉か一目で分かるように
- たまっている券は**回数券のかたち**（左右にへこみ）。数字だけ書くより、持ちものとして見えたほうがためる気になる。7日に足りないときは、下に伸びる帯であと何日かを出す

#### 回す動画

`app/gacha.ts` の各回の `video`。いまは3つとも `public/gacha/win.mp4`（360×640・音なし・H.264・6.3秒・約570KB）。

引くボタンを押すと流し、**終わったところで結果を出す**。

- **はずれのときは `videoStopAt`（1.85秒）で止める。** 動画は最後に「当たり」の札が出るところまで入っているので、はずれた人にそれを見せてから「はずれ」と言うのは裏切りになる。ハンドルを回し終わったあたりで切る
- そのため**結果を先に受け取ってから流す**（どこで止めるかは結果が分からないと決まらない）
- **流している最中に舞台を押すと飛ばせる。** 毎日見るものなので、待つだけの時間にしない
- 1枚目には `machine` の絵を敷いてある（`poster`）。この絵は**動画の1コマ目から作った**ので、再生が始まった瞬間に絵が飛ばない
- 読めない・流せないときは**絵に落ちて左右に揺れる**。差し替えで画面が壊れない
- 流し終わらないときのために**10秒で打ち切る**。止まったままにしない
- 動画そのものが動くので、そのときは揺らさない（二重に動くと酔う）

**必ず H.264（avc1）の mp4 にすること。** webm や、H.264以外を包んだ mp4 は iPhone の Safari で再生できない。会員のほとんどが iPhone なので、そこで動かないものを既定にしない。

差し替えるときは `ffmpeg` で作り直す（開発用に `npm i --no-save ffmpeg-static` で入る）。もとの動画から:

```
ffmpeg -t 8.2 -i もとの動画.mp4 -vf "scale=360:640,setpts=PTS/1.3" -an \
  -c:v libx264 -profile:v main -pix_fmt yuv420p -crf 26 -r 24 \
  -movflags +faststart public/gacha/win.mp4
# 1コマ目を止め絵に
ffmpeg -i もとの動画.mp4 -vf "scale=360:640" -frames:v 1 public/gacha/machine.webp
```

**切るのは入力側（`-i` より前）に `-t` を置く。** 出力側に置くと、早送りしたぶん長く読んでしまい、要らない最後の場面まで入る。

#### ガチャ本体の絵

`app/gacha.ts` の各回の `machine`。いまは3つとも `public/gacha/machine.webp`（縦長）を使っている。回しているあいだ**この絵ごと揺れる**。回ごとに差し替えられるので、クリスマス仕様・お正月仕様の本体を用意したらパスを変える。置いていない・読めないときは、絵は出ない（賞の一覧と引くボタンだけになる）。

### 当たり

**等級（A賞・B賞）＋中身**の形で出す。等級は `prize.tier`、中身は `prize.label`。はずれは `tier` を空にする（画面では「—」になる）。

| 等級 | ふだん | クリスマス | お正月 | 券 | 確率 |
|---|---|---|---|---|---|
| A賞 | 広告の無料券 3日分 | 大きなプレゼント | 大吉 | 3日分 | 8% |
| B賞 | 広告の無料券 1日分 | プレゼント | 中吉・小吉 | 1日分 | 37% |
| —  | はずれ | くつ下は空っぽ | 吉・末吉 | なし | 55% |

一覧では、名前がそのまま中身になっている回（ふだんの回）で右の日数を出さない。同じことを2度書かないため。おみくじのように名前と中身が違う回だけ、右に「無料券 3日分」と添える。

1回あたりの期待値は **0.61日**。毎日引くと**12日ほどで月の上限（7日）**に届く。

### なぜ小さい券を積み上げる形なのか

広告は7日からしか申し込めない（`AD_MIN_DAYS`）。**1日券だけでも7日ためれば1週間まるごと無料で出せる。** 大きい当たりを低い確率で当てるより、毎日ちょっとずつ増えるほうが、毎日開く理由になる。画面には「あと◯日分で1週間出せます」と出している。

### なぜ上限が「月ごと」なのか

終わりの無い催しなので、**通算で上限を置くと、一度届いた人はそのあとずっと何ももらえなくなり、毎日引く意味が消える。** 毎月1日に戻す。

### いくらぶん配ることになるか

バナーは1日350円・1日10枠＝月300枠日。

- 月の上限100日＝ **35,000円ぶん／月**。バナーの3分の1
- 40人が1人7日ずつ取ると280日だが、全体の上限100日で止まる
- **減らしたくなったら `capDaysPerMonth` を下げる。**すでに配ったぶんは戻らない

## 作りで守っていること

- **抽選はサーバーで引く**（`drawGacha`）。画面で引くと、当たるまで押し直せる
- 乱数は `crypto.getRandomValues`。`Math.random` は実装によって種を推測できる
- 書き込みは `INSERT OR IGNORE` で行い、**そのあと読み直した行を正とする**。連打や通信のやり直しで2回届いても、勝つのは先に入った1行だけ。「引いたか」を先に調べてから書くと、その隙間に2回目が入る
- 期間も「今日」も「今月」も**日本時間**で判定する。UTCで比べると、日本の0時〜8時59分が前日扱いになる
- 上限までの残りが当たりの日数に足りないときは、**減らして渡さず「はずれ」にする**。「3日分」と出しておいて1日しか入らないほうが、はずれより裏切りになる
- 連続日数は**回に関係なく**数える。クリスマスから正月へ変わっただけで連続が切れると、続けている人ほど損をする
- 券は `ad_gifts` に日数で持ち、**古いものから使う**。使うのは掲載日数を全部まかなえるときだけ。足りないぶんを値引きにすると、支払いが途中で止まったときに券だけ消える
- 券だけで足りる申し込みは **Stripeを通さず、その場で掲載を始める**。券を減らすのは掲載を始めたあと
- 券で出した枠は売上**0円**として記録する。広告の売上に混ぜない
- お支払いの用意（Stripeの鍵）ができていなくても、**券だけで出せる申し込みは通す**

## 運営の見かた

管理画面のダッシュボードに、**今月の**「引いた人／のべ回数／配った枠」と上限、回ごとの内訳、そのうしろに通算が出る。**引いた回数より「何日配ったか」を見ること。**

## 変えるとき

`app/gacha.ts` を書き替えて push すれば、そのまま効く。

- 季節の回を足す・変える … `seasons` に足す（**日付なしの回はいちばん下のまま**）
- 当たりやすさを変える … 各回の `prizes` の `weight`
- 配りすぎを止める … `capDaysPerMonth`（全体）と `memberCapDaysPerMonth`（1人）
- 券の持ち期間 … `giftValidDays`（いまは90日）
- **ガチャを止める** … `seasons` を空にする。画面から入口ごと消える

7日未満の券しか出ない設計でも構わないが、**7日ためるまで使えない**ことは画面で必ず伝えること（いまは「あと◯日分」と出している）。

## 表について

`gacha_days` が使っているほう。`gacha_draws`（1人1回だったころの表）は残してあるが、もう読み書きしていない。**消さない** — 消すと、この名前で残っている古い記録が読めなくなる。
