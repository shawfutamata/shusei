# 毎日ガチャ（広告の無料券）

更新日: 2026-09-03

## 何のためにやるか

ねらいは2つ。

1. **毎日ここを開く理由を作ること。** 掲示板は「見に来る習慣」がついて初めて回る。1日1回だけ引ける形にしてあるのはそのため。
2. **掲示板の上を埋めること。** 開いたばかりの掲示板は広告の枠が空いていて、空いた枠は売っても埋まらない。誰も出していないところに最初に出すのは決心が要る。配って埋めてしまえば、次に買う人は「こう出るのか」を見てから決められる。

売上を狙うものではない。**配った枠のぶんだけ、売れる枠は減っている。**

## 決まりごと

| | |
|---|---|
| いつ引けるか | **いつでも。終わりを決めていない催し。** 1人1日1回 |
| 回数の守り方 | `gacha_days` の主キー（member_id, day）。日付は日本時間 |
| 1人の上限 | **月7日分**。届いたあとも引けるが、券は増えない |
| 全体の上限 | **月100日分**。届いたら誰が引いても券は出ない |
| 上限が戻る日 | 毎月1日（日本時間） |
| 券の期限 | **当たった日から90日** |

### 見た目は季節で変わる

**中身（確率と日数）は同じで、包み紙だけ変える。**

| 期間 | 回 | 見た目 |
|---|---|---|
| ふだん | 毎日ガチャ | 四つ葉・アプリの青 |
| 12/20〜12/25 | クリスマスガチャ | プレゼント箱・赤と緑 |
| 12/26〜1/7 | お正月おみくじ | 門松・紅白と金（大吉〜末吉） |

`gachaSeason()` は **上から順に見て最初に当てはまった回**を返す。日付を入れていない「ふだんの回」は必ずいちばん下に置くこと。次の季節の回は「12月20日から クリスマスガチャ が始まります」と先に知らせている。

### 当たり

| ふだん | クリスマス | お正月 | 券 | 確率 |
|---|---|---|---|---|
| 当たり | 大きなプレゼント | 大吉 | 3日分 | 8% |
| 小当たり | プレゼント | 中吉・小吉 | 1日分 | 37% |
| はずれ | くつ下は空っぽ | 吉・末吉 | なし | 55% |

1回あたりの期待値は **0.61日**。毎日引くと**12日ほどで月の上限（7日）**に届く。

### なぜ小さい券を積み上げる形なのか

広告は7日からしか申し込めない（`AD_MIN_DAYS`）。**1日券だけでも7日ためれば1週間まるごと無料で出せる。** 大きい当たりを低い確率で当てるより、毎日ちょっとずつ増えるほうが、毎日開く理由になる。画面には「あと◯日分で1週間出せます」と出している。

### なぜ上限が「月ごと」なのか

終わりの無い催しなので、**通算で上限を置くと、一度届いた人はそのあとずっと何ももらえなくなり、毎日引く意味が消える。** 毎月1日に戻す。

### いくらぶん配ることになるか

バナーは1日350円・1日10枠＝月300枠日。

- 月の上限100日＝ **35,000円ぶん／月**。バナーの3分の1
- 40人が1人7日ずつ取ると280日だが、全体の上限100日で止まる
- **減らしたくなったら `capDaysPerMonth` を下げる。**すでに配ったぶんは戻らない

## 作りで守っていること

- **抽選はサーバーで引く**（`drawGacha`）。画面で引くと、当たるまで押し直せる
- 乱数は `crypto.getRandomValues`。`Math.random` は実装によって種を推測できる
- 書き込みは `INSERT OR IGNORE` で行い、**そのあと読み直した行を正とする**。連打や通信のやり直しで2回届いても、勝つのは先に入った1行だけ。「引いたか」を先に調べてから書くと、その隙間に2回目が入る
- 期間も「今日」も「今月」も**日本時間**で判定する。UTCで比べると、日本の0時〜8時59分が前日扱いになる
- 上限までの残りが当たりの日数に足りないときは、**減らして渡さず「はずれ」にする**。「3日分」と出しておいて1日しか入らないほうが、はずれより裏切りになる
- 連続日数は**回に関係なく**数える。クリスマスから正月へ変わっただけで連続が切れると、続けている人ほど損をする
- 券は `ad_gifts` に日数で持ち、**古いものから使う**。使うのは掲載日数を全部まかなえるときだけ。足りないぶんを値引きにすると、支払いが途中で止まったときに券だけ消える
- 券だけで足りる申し込みは **Stripeを通さず、その場で掲載を始める**。券を減らすのは掲載を始めたあと
- 券で出した枠は売上**0円**として記録する。広告の売上に混ぜない
- お支払いの用意（Stripeの鍵）ができていなくても、**券だけで出せる申し込みは通す**

## 運営の見かた

管理画面のダッシュボードに、**今月の**「引いた人／のべ回数／配った枠」と上限、回ごとの内訳、そのうしろに通算が出る。**引いた回数より「何日配ったか」を見ること。**

## 変えるとき

`app/gacha.ts` を書き替えて push すれば、そのまま効く。

- 季節の回を足す・変える … `seasons` に足す（**日付なしの回はいちばん下のまま**）
- 当たりやすさを変える … 各回の `prizes` の `weight`
- 配りすぎを止める … `capDaysPerMonth`（全体）と `memberCapDaysPerMonth`（1人）
- 券の持ち期間 … `giftValidDays`（いまは90日）
- **ガチャを止める** … `seasons` を空にする。画面から入口ごと消える

7日未満の券しか出ない設計でも構わないが、**7日ためるまで使えない**ことは画面で必ず伝えること（いまは「あと◯日分」と出している）。

## 表について

`gacha_days` が使っているほう。`gacha_draws`（1人1回だったころの表）は残してあるが、もう読み書きしていない。**消さない** — 消すと、この名前で残っている古い記録が読めなくなる。
