# トップバナーの出稿枠

更新日: 2026-08-29

会費と並ぶ、もうひとつの収入源。**1枠 10,000円・同時に10本まで・早い者勝ち**で、上位ランクの会員だけが買える。掲載する期間はカレンダーから選ぶ（既定は最大30日）。

## なぜこの形にしたか

| 決めたこと | 理由 |
|---|---|
| **上位ランク（RUBY以上）限定** | 「払えば誰でも目立てる」にすると、紹介し合う場という前提が崩れる。ランクは紹介の実績で上がるので、広告枠が紹介を続ける動機になる |
| **都度払い** | 購読にすると解約の手間と問い合わせが増える。掲載したい期間だけ買ってもらう |
| **同時に10本** | 増やすほど1枠の価値が下がる。10本なら、自動送りで1周する間にひととおり目に入る。空きは**日ごと**に見るので、期間の組み方は自由 |
| **早い者勝ち** | 誰を載せるか運営が選ばないので、審査の手間も、選ばれなかった人への説明も要らない |
| **カルーセルの先頭** | お金をいただいている枠なので、いちばん先に目に入る場所に置く。案内バナー3枚はそのうしろ |

## 出稿者に返すもの

次も買うかどうかは、ここの数字で決まる。マイページの出稿カードに出している。

| 数字 | 数え方 |
|---|---|
| **見た人** | バナーが実際に画面に出た回数。**同じ会員・同じ広告は1日1回まで**。間引きは端末側（localStorage / アプリはメモリ）でやってから送る |
| **押された** | バナーを押した回数。もともと少ないので、その場で1件書く |
| **反応** | 押された ÷ 見た人 |
| **日ごとの推移** | `ad_daily` に1日1行で貯める。グラフと表の両方で見られる |

表示とクリックは桁が違うので、**1つのグラフに2本の軸を置かない**。同じ日付の目盛りを共有した2枚の棒グラフに分ける（読み違えようがない形）。

終わったぶんも**90日**は見返せる（`listMemberAds()`）。「10,000円で何人に届いたか」を見てから、次を買うかどうか決められるようにするため。

### 書き込み回数を増やさないための作り

掲示板を開くたびにD1へ書くと、書き込み回数が読めなくなる。そこで:

- **間引きは端末側**。同じ広告は1日1回しか送らない（Webは `tasuki-ad-seen-v1:YYYY-MM-DD`、日付が変わると前日ぶんを消す）
- **送るのは1回**。`POST /api/ads/track` に見たぶんをまとめて渡し、`env.DB.batch()` で1往復にする
- **送信は `navigator.sendBeacon`**。画面を離れても落ちない。使えない環境では `fetch(keepalive)`

会員1,000人・10本が全部埋まっている日で、書き込みは1日最大20,000回（合計と日ごとの2本立てのため）。D1の無料枠（1日100,000回）に収まる。

## 買ってから出るまで

```
広告メニュー → 5つ（タイトル・説明文・リンク・画像・期間）を入れる → 申し込む
  ↓ 枠を1つ押さえ、同時に中身も入れる（status='reserved'）
  ↓ Stripeの支払い画面（mode='payment'・1回きり）
  ↓ webhook が checkout.session.completed を受ける
  ↓ status='active' になり、そのままホームのバナーに出る
戻ってきた画面（/?ad=done）→ 出稿の設定モーダルが自動で開く
```

- 決済画面を開けなかったときは、押さえた枠を**その場で返す**（`releaseAdSlot()`）
- 支払わずに放置された枠は**60分**で解放される（`AD_RESERVATION_MINUTES`）
- 同時に最後の1枠を取り合ったときは、後から入ったほうが自分の予約を消して負けを認める（`reserveAdSlot()`）

## 出稿する人が入れるのは5つだけ

**バナーを自分で作らせない。** 入れてもらうのはこれだけで、並べ方はこちらで決める。

| 入れるもの | 上限 | 必須 |
|---|---|---|
| タイトル | 30文字 | 必須 |
| 説明文 | 60文字 | 任意 |
| リンク | 200文字 | 任意 |
| 画像 | JPEG/PNG/WebP | 任意 |
| 投稿期間 | カレンダーで開始日＋日数（既定は最大30日） | 必須 |

バナーは `app/AdBanner.tsx` が組み立てる。写真の上に暗いグラデーションを敷き、その上にタイトルと説明文を重ねる。**写真が無くても紺の下地で成立する**ので、画像は任意にできる。入稿画面のプレビューも掲載も、この同じ部品で描いている。見えているものが、そのまま載る。

### 出す流れは3つの手順

1画面に全部並べると2.4画面ぶんの縦長になり、どこまでやったのか分からなくなる。だから **①内容 → ②期間 → ③確認** に分けてある。1つの手順がだいたい1画面に収まる。

- **①内容** … 4つを入れて、その場で「ホームでの見え方」を見る
- **②期間** … カレンダーで始める日を押し、日数を決める。カレンダーは**1ヶ月ずつ送る**（何ヶ月も縦に並べると、どこを見ればいいのか分からなくなる）。満枠の日をまたぐ期間は選べず、直し方を文で出す
- **③確認** … 出来上がりのバナー・期間・リンク・料金を並べて、お支払いへ

**申し込みと入稿は1つの流れ**。5つを入れて申し込むと、押さえるのと同時に中身が入る。だから「買ったのに何も出ていない枠」ができない。決済に失敗したら、枠も中身もその場で消える。

すでに枠を持っている人には、その枠と成果だけを見せて、「新しく出す」を押したときにこの流れへ入る。

画像の縮小は出す人の端末でやる（`app/resize-image.ts`）。サーバーでは変換しない。

## 運営がやること## 運営がやること

**ふだんは何もしない。** 審査も、掲載の切り替えも、請求も自動で回る。

止めるときだけ手を入れる。法令や公序良俗に反する掲載を見つけた場合（利用規約 第9条）:

```bash
# 掲載を止める。ホームのバナーから外れ、出稿者の画面には「掲載を停止しています」と出る
npx wrangler d1 execute <D1_DATABASE> --remote \
  --command "UPDATE ad_slots SET status='stopped' WHERE id='<枠のID>'"
```

止めた場合の返金は「返金・キャンセルポリシー」7項のとおり（掲載前なら全額、掲載後は残り日数ぶん）。

## 置き場所

| 場所 | 役割 |
|---|---|
| `app/ad-options.ts` | 枠数・ランク条件・文字数の上限・予約の有効時間。**金額は入れない**（クライアントから読むため） |
| `app/plan-catalog.ts` | `AD_SLOT_YEN`（10,000円）。**Web専用** |
| `app/AdBanner.tsx` | 入力からバナーを組み立てる。掲載もプレビューも同じ部品 |
| `app/ad-upload.ts` | 入力の受け取りと検査。申し込みと入れ替えの両方から使う |
| `app/AdAnalytics.tsx` | 成果のグラフと表 |
| `db/data.ts` | 枠の押さえ方、掲載の読み出し、成果の数え上げ |
| `GET /api/ads` | 申し込めるカレンダーと日ごとの空き、自分の枠。**Web専用** |
| `GET /api/ads/[id]/stats` | 日ごとの表示とクリック。**Web専用** |
| `POST /api/ads/checkout` | 5つを受け取り、枠を押さえてStripeへ。**Web専用** |
| `POST /api/ads/[id]` | 掲載内容の入れ替え。**Web専用** |
| `POST /api/ads/track` | 見た数と押された数。金額に触れないのでアプリからも呼ぶ |
| `GET /api/ad-image/[id]` | バナー画像。版番号つきURLなので1年キャッシュ |

## アプリとの関係（ストア審査）

**掲載は出す。申し込みは出さない。**

- アプリのホームにも同じ広告が並ぶ（出稿者から見て「Webの人にしか届かない」を避けるため）
- アプリには**価格も申し込みボタンも出さない**（App Store 3.1.1）。買うのはWebだけ
- 成果の数え上げ（`/api/ads/track`）は金額に触れないので、アプリから呼んでよい

## 決まっていないこと

- **日数によって値段を変えていない。** 1枠10,000円で、1日でも30日でも同じ。30日いっぱい使う人がほとんどになるはずなので、実質「30日 10,000円」。日割りにするならStripeを `price_data` に変える必要がある
- 同じ人が期間を重ねて複数枠を買えてしまう。いまは止めていない（枠が余っていれば買えたほうがよい、という判断）
- 掲載開始の前日に知らせる通知。入稿を忘れたまま始まる人が出たら入れる
