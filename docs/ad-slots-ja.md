# トップバナーの出稿枠

更新日: 2026-08-29

会費と並ぶ、もうひとつの収入源。**1枠1ヶ月 10,000円・月10枠・早い者勝ち**で、上位ランクの会員だけが買える。

## なぜこの形にしたか

| 決めたこと | 理由 |
|---|---|
| **上位ランク（RUBY以上）限定** | 「払えば誰でも目立てる」にすると、紹介し合う場という前提が崩れる。ランクは紹介の実績で上がるので、広告枠が紹介を続ける動機になる |
| **1ヶ月ごとの都度払い** | 購読にすると解約の手間と問い合わせが増える。掲載したい月だけ買ってもらう |
| **月10枠** | 増やすほど1枠の価値が下がる。10枠なら、自動送りで1周する間にひととおり目に入る |
| **早い者勝ち** | 誰を載せるか運営が選ばないので、審査の手間も、選ばれなかった人への説明も要らない |
| **カルーセルの先頭** | お金をいただいている枠なので、いちばん先に目に入る場所に置く。案内バナー3枚はそのうしろ |

## 出稿者に返すもの

次も買うかどうかは、ここの数字で決まる。マイページの出稿カードに出している。

| 数字 | 数え方 |
|---|---|
| **見た人** | バナーが実際に画面に出た回数。**同じ会員・同じ広告は1日1回まで**。間引きは端末側（localStorage / アプリはメモリ）でやってから送る |
| **押された** | バナーを押した回数。もともと少ないので、その場で1件書く |
| **反応** | 押された ÷ 見た人 |

終わった月のぶんも**3ヶ月**は見返せる（`listMemberAds()`）。「先月は10,000円で何人に届いたか」を見てから、来月を買うかどうか決められるようにするため。

### 書き込み回数を増やさないための作り

掲示板を開くたびにD1へ書くと、書き込み回数が読めなくなる。そこで:

- **間引きは端末側**。同じ広告は1日1回しか送らない（Webは `tasuki-ad-seen-v1:YYYY-MM-DD`、日付が変わると前日ぶんを消す）
- **送るのは1回**。`POST /api/ads/track` に見たぶんをまとめて渡し、`env.DB.batch()` で1往復にする
- **送信は `navigator.sendBeacon`**。画面を離れても落ちない。使えない環境では `fetch(keepalive)`

会員1,000人・10枠が全部埋まった月で、書き込みは1日最大10,000回。D1の無料枠（1日100,000回）に収まる。

## 買ってから出るまで

```
マイページ → 掲載する月を選ぶ → 申し込む
  ↓ 枠を1つ押さえる（status='reserved'）
  ↓ Stripeの支払い画面（mode='payment'・1回きり）
  ↓ webhook が checkout.session.completed を受ける
  ↓ status='active' になる
戻ってきた画面（/?ad=done）→ マイページの出稿カードへ自動で移動
  ↓ 見出し・リンク・画像を入れる
ホームのバナーに出る
```

- 決済画面を開けなかったときは、押さえた枠を**その場で返す**（`releaseAdSlot()`）
- 支払わずに放置された枠は**60分**で解放される（`AD_RESERVATION_MINUTES`）
- 同時に最後の1枠を取り合ったときは、後から入ったほうが自分の予約を消して負けを認める（`reserveAdSlot()`）

## 画像を持っていない人向けの作り

経営者が自分で3:2のバナーを作れるとは限らない。作れないと、買ったのに何も出ない枠になる。

そこで**「文字だけで作る」**を用意した。見出しと会社名・お名前から、端末の中でバナーを1枚描いて、画像を選んだときと同じ経路で送る（`app/ad-banner.ts`）。

- 色は4つから選ぶ（紺・橙・墨・生成り）
- 打ちながら**ホームでの見え方**が更新される。掲載時に左上へ重なる「PR」の札を避けた位置に描いているので、見えたままが載る
- **サーバーでは画像を作らない**。Workersの計算時間は従量なので、ここで作業させない

## 運営がやること

**ふだんは何もしない。** 審査も、掲載の切り替えも、請求も自動で回る。

止めるときだけ手を入れる。法令や公序良俗に反する掲載を見つけた場合（利用規約 第9条）:

```bash
# 掲載を止める。ホームのバナーから外れ、出稿者の画面には「掲載を停止しています」と出る
npx wrangler d1 execute <D1_DATABASE> --remote \
  --command "UPDATE ad_slots SET status='stopped' WHERE id='<枠のID>'"
```

止めた場合の返金は「返金・キャンセルポリシー」7項のとおり（掲載前なら全額、掲載後は残り日数ぶん）。

## 置き場所

| 場所 | 役割 |
|---|---|
| `app/ad-options.ts` | 枠数・ランク条件・見出しの長さ・予約の有効時間。**金額は入れない**（クライアントから読むため） |
| `app/plan-catalog.ts` | `AD_SLOT_YEN`（10,000円）。**Web専用** |
| `app/ad-banner.ts` | 文字だけのバナーを端末で描く |
| `db/data.ts` | 枠の押さえ方、掲載の読み出し、成果の数え上げ |
| `GET /api/ads` | 申し込める月と残り枠、自分の枠と成果。**Web専用** |
| `POST /api/ads/checkout` | 枠を押さえてStripeへ。**Web専用** |
| `POST /api/ads/[id]` | 見出し・リンク・画像の入稿。**Web専用** |
| `POST /api/ads/track` | 見た数と押された数。金額に触れないのでアプリからも呼ぶ |
| `GET /api/ad-image/[id]` | バナー画像。版番号つきURLなので1年キャッシュ |

## アプリとの関係（ストア審査）

**掲載は出す。申し込みは出さない。**

- アプリのホームにも同じ広告が並ぶ（出稿者から見て「Webの人にしか届かない」を避けるため）
- アプリには**価格も申し込みボタンも出さない**（App Store 3.1.1）。買うのはWebだけ
- 成果の数え上げ（`/api/ads/track`）は金額に触れないので、アプリから呼んでよい

## 決まっていないこと

- 同じ人が同じ月に複数枠を買えてしまう。いまは止めていない（枠が余っていれば買えたほうがよい、という判断）
- 掲載開始の前日に知らせる通知。入稿を忘れたまま月が変わる人が出たら入れる
